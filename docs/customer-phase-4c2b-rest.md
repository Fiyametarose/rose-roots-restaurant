# Customer Phase 4C.2B — connected REST

## Windows launch

A nonblank backend origin selects connected mode. Use the explicit flag to require connected mode even if configuration is missing. The origin must be HTTPS with a trusted certificate matching the configured host. The terminal token file must contain the bearer credential issued by Admin. Keep it outside the repository and restrict its Windows ACL to the Customer launcher account. Restart Customer after rotating the provisioning file. No credential is generated by the launcher.

```powershell
$env:ROSE_ROOTS_BACKEND_URL = 'https://restaurant-pc.example:8443'
$env:ROSE_ROOTS_TERMINAL_TOKEN_FILE = 'C:\secure\rose-roots-terminal.token'
.\gradlew.bat :customer:run --args="--connected"
```

An unconfigured ordinary launch preserves the existing local draft mode. Explicit `--demo-table`, `--demo-takeaway` and `:customer:runDemo` choose the local demo even when an origin is configured. A connection, credential or API failure in connected mode leaves it disconnected and does not select local sessions or a fixture catalog. The Welcome retry stays on the same route. Menu and tracking refresh without blocking JavaFX. This phase uses REST polling while My Orders is open. The previous WSS transport and reconnect classes remain available for later integration.

## REST mapping

| Operation | Source and verified client behavior |
| --- | --- |
| GET /api/v1/device, POST /api/v1/sessions | Ordering draft. Attach terminal bearer, validate returned scope and Table 07 through the authoritative device mapping, accept 201 creation and 200 resumption. The app checks open state, expiry and matching Dine-In assignment before entering the menu. Takeaway requires an authoritative pickup reference. |
| GET /api/v1/menu | Existing Admin CatalogController and CatalogData.Snapshot. Preserve server item/category/group/choice identifiers and decimal catalog prices for browsing. Use same-origin public menu image references. Imported source metadata is excluded from safety judgments. Cross-contact and completeness are not supplied by the public catalog response. |
| POST /api/v1/order-quotes, POST /api/v1/orders | Existing ordering draft and state machine. Only authoritative quotes enable submission. Uncertain responses retain the original request and key for approved replay; the cart clears matching submitted lines only on validated acceptance. |
| GET /api/v1/orders/{id} | Read by server UUID after acceptance; validate both order and session ID. A readback outage leaves the accepted response visible. |
| GET /api/v1/sessions/{id}/orders and /bill | Reuse session-scoped paginated order history and authoritative combined totals. REST polls serially while tracking is open. The screen discards replaced subscriptions and retains the last coherent snapshot on error. |

## Owners and dependencies

- **Admin** must publish terminal credential provisioning and the device/table/session endpoints with an authorized test terminal; expose the shared catalog and finish the joint server and PostgreSQL assembly. The inspected Admin tree has public menu/category endpoints, Manager endpoints and LAN configuration. No connected test origin or issued terminal credential was available in this workspace. The default local LAN port had no listener.
- **Admin + Customer** must reconcile customization references. Admin currently models group and option IDs as arbitrary strings. The approved order draft uses UUIDs for both. The client displays and retains existing values and rejects non-UUID selections before quoting. It never invents mappings or silently drops options. A first item with no required selections or with server-provided UUID options avoids the discrepancy.
- **Customer + Admin** must implement and expose order quotes, submission, accepted order readback, and session order/bill persistence under the existing paths. Controlled tests do not establish a live deployment.
- **Kitchen** must provide shared persisted eligible-line changes and validate the allergy gate. Live WSS, pre-order estimates and Assistance wire integration remain separate. Customer retains the existing unavailable behavior for those services.

The tests use a local HTTPS server with a temporary certificate and isolated test fixtures. That deliberately induced timeout and replay test is not evidence of a genuine two-PC or shared PostgreSQL order.
